## What are Check Blocks?

**Check blocks** are used to run **custom validations on infrastructure after deployment**.

They help verify that the infrastructure **meets certain conditions without stopping resource creation**.

Unlike preconditions or postconditions, check blocks are mainly used for **validation and monitoring**, not controlling resource execution.

---

## Basic Syntax

check "instance_running" {  
  assert {  
    condition     = aws_instance.app.instance_state == "running"  
    error_message = "EC2 instance is not running."  
  }  
}

---

## How It Works

- Runs **after Terraform evaluates resources**.
    
- Validates infrastructure state using **assert conditions**.
    
- If the condition fails, Terraform **reports the check failure**.
    

---

## Example

resource "aws_instance" "app" {  
  ami           = "ami-123456"  
  instance_type = "t2.micro"  
}  
  
check "verify_instance" {  
  assert {  
    condition     = aws_instance.app.instance_state == "running"  
    error_message = "Instance must be in running state."  
  }  
}

---

## Important Points

- Uses **`assert` blocks** to define conditions.
    
- Multiple **assert statements** can be used inside a check.
    
- Mainly used for **post-deployment validation**.
    
- Does **not control resource creation** like pre/postconditions.
    

---

## Check vs Preconditions/Postconditions

|Feature|Check Block|Preconditions/Postconditions|
|---|---|---|
|Purpose|Validation & monitoring|Control resource behavior|
|When it runs|After infrastructure evaluation|Before or after resource execution|
|Scope|Global checks|Resource-specific checks|

---

## Quick Summary

- **Check blocks verify infrastructure state.**
    
- Use **assert conditions** to validate outputs or resources.
    
- Mainly used for **post-deployment verification**.
