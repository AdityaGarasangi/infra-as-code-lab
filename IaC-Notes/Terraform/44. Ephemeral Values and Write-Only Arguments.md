## 1. Ephemeral Values

### What are Ephemeral Values?

**Ephemeral values** are temporary values that **exist only during Terraform execution** and are **NOT stored in the state file**.

Used for **sensitive or short-lived data**.

---

### Why Use Them?

- Avoid storing secrets in state
- Handle **temporary credentials**
- Improve security

---

### Example Concept

# Conceptual example  
```
resource "example" "test" {  
  password = ephemeral("temp-password")  
}
```
Value is used during apply but **not persisted in state**.

---

### Key Points

- Not saved in `terraform.tfstate`
- Useful for **tokens, one-time secrets**
- Reduces **risk of secret leakage**

---

## 2. Write-Only Arguments

### What are Write-Only Arguments?

**Write-only arguments** are resource arguments that:

- Can be **set during creation**
- But **cannot be read back by Terraform**

Terraform does NOT store or retrieve their value.

---

### Example

```
resource "aws_db_instance" "db" {  
  password = var.db_password  
}
```

Password is:

- Sent to AWS 
- Not readable later 

---

## Why They Matter

Both help with **secure secret handling**:

|Feature|Ephemeral Values|Write-Only Arguments|
|---|---|---|
|Stored in state|No|No (or masked)|
|Readable later|No|No|
|Use case|Temporary values|Sensitive inputs|

---

## Important Notes

- Not all providers support **write-only arguments**.
- Ephemeral values are **execution-time only**.
- Still combine with:
    - Vault
    - Remote backend encryption

---

## Quick Summary

- **Ephemeral values → temporary, not stored anywhere**
- **Write-only arguments → sent but never retrievable**
- Both improve **security in Terraform workflows**
