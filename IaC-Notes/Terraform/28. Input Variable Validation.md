## What is Variable Validation?

Variable validation allows you to **define rules for input variables** to ensure users provide **valid values**.

Terraform checks these conditions during **`terraform plan`** and throws an error if the validation fails.

---

## Syntax

variable "instance_type" {  
  type = string  
  
  validation {  
    condition     = var.instance_type == "t2.micro"  
    error_message = "Instance type must be t2.micro."  
  }  
}

---

## Example

variable "instance_count" {  
  type = number  
  
  validation {  
    condition     = var.instance_count > 0  
    error_message = "Instance count must be greater than 0."  
  }  
}

---

## Using Functions in Validation

You can use Terraform functions like `contains()`, `length()`, etc.

variable "environment" {  
  type = string  
  
  validation {  
    condition     = contains(["dev", "staging", "prod"], var.environment)  
    error_message = "Environment must be dev, staging, or prod."  
  }  
}

---

## Important Points

- Validation runs during **`terraform plan`**.
    
- Helps **prevent invalid infrastructure configuration**.
    
- Improves **input safety and error clarity**.
    
- Multiple validation blocks can be used if needed.
    

---

## Quick Summary

|Feature|Description|
|---|---|
|Purpose|Enforce rules on input variables|
|Checked During|`terraform plan`|
|Key Fields|`condition`, `error_message`|
|Benefits|Prevents invalid user input|

## Preconditions and Postconditions
Preconditions and postconditions are **custom checks** used to validate assumptions **before or after a resource is created**.

They help ensure infrastructure behaves as expected and prevent incorrect deployments.

---

## Preconditions

A **precondition** checks a condition **before Terraform creates or updates a resource**.

If the condition fails, Terraform **stops the plan/apply process**.

### Example

resource "aws_instance" "app" {  
  ami           = "ami-123456"  
  instance_type = "t2.micro"  
  
  lifecycle {  
    precondition {  
      condition     = var.instance_count > 0  
      error_message = "Instance count must be greater than 0."  
    }  
  }  
}

---

## Postconditions

A **postcondition** checks a condition **after the resource is created**.

Used to verify the **result of the resource**.

### Example

resource "aws_instance" "app" {  
  ami           = "ami-123456"  
  instance_type = "t2.micro"  
  
  lifecycle {  
    postcondition {  
      condition     = self.instance_state == "running"  
      error_message = "EC2 instance must be running."  
    }  
  }  
}

`self` refers to the **current resource being evaluated**.

---

## Key Differences

|Feature|Precondition|Postcondition|
|---|---|---|
|When it runs|Before resource creation|After resource creation|
|Purpose|Validate inputs or assumptions|Validate resource results|
|Reference|Variables, expressions|Uses `self` for resource attributes|

---

## Important Points

- Defined inside the **`lifecycle` block**.
    
- Useful for **safety checks and policy enforcement**.
    
- Helps detect **misconfiguration early**.
    
- `self` keyword is used to reference the **current resource**.
    

---

## Quick Summary

- **Precondition → before resource execution**
    
- **Postcondition → after resource execution**
    
- Used for **runtime validation of infrastructure behavior**
