### What is Resource Behaviour

- **Resource behavior** defines how Terraform creates, updates, or destroys resources.
    
- This behavior can be controlled using **meta arguments** inside resource blocks.
    

---

### What are Meta Arguments?

- Meta arguments are **special arguments supported by all (or most) resources**.
    
- They are used to **control execution, lifecycle, and dependencies**, not the resource itself.
    

---

## Common Meta Arguments

---

### 1️⃣ `count`

- Creates **multiple instances of a resource**.
```
resource "aws_instance" "web" {  
  count         = 3  
  ami           = "ami-123"  
  instance_type = "t3.micro"  
}
```
Access:

```
aws_instance.web[0].id
```

---

### 2️⃣ `for_each`

- Creates multiple resources using a **map or set**.
- `for_each` is used to **create multiple instances of a resource or module** using a **map or set of values**.
- Instead of duplicating code, Terraform loops over a collection.
```
resource "aws_instance" "web" {  
  for_each = {  
    app1 = "t3.micro"  
    app2 = "t3.small"  
  }  
  
  instance_type = each.value  
}
```

Access:
```
aws_instance.web["app1"].id
```

* Example
```
resource "aws_instance" "app" {
  for_each = toset(["dev", "staging", "prod"])

  ami           = "ami-123456"
  instance_type = "t2.micro"

  tags = {
    Name = each.key
  }
}
```
## Key Concepts
### `each.key`
- Represents the **current item**
- Used when iterating over sets or maps
### `each.value`
- Represents the **value of the current item**
- Mostly used with maps

---

### 3️⃣ `depends_on`

- Explicitly defines dependencies when Terraform **cannot detect them automatically**.
```
resource "aws_instance" "web" {  
  depends_on = [aws_security_group.sg]  
}
```

---

### 4️⃣ `lifecycle`

- Controls how Terraform handles **resource changes**.
```
resource "aws_instance" "web" {  
  lifecycle {  
    create_before_destroy = true  
  }  
}
```

Common lifecycle options:

|Argument|Purpose|
|---|---|
|create_before_destroy|Create new resource before deleting old|
|prevent_destroy|Prevent accidental deletion|
|ignore_changes|Ignore specific attribute changes|

Example:
```
lifecycle {  
  ignore_changes = [tags]  
}
```

---

### 5️⃣ `provider`

- Specifies which provider configuration to use.
```
resource "aws_instance" "web" {  
  provider = aws.us_east  
}
```

---

## Resource Behavior Control (Important Concepts)

---

### 🔹 Create → Update → Destroy Flow

- Terraform follows this lifecycle:
```
Create → Update → Destroy
```

- If a change requires replacement:
```
Destroy → Create   (default)
```
- With lifecycle:
```
Create → Destroy   (no downtime)
```

---
* **Create resources** that exist in the configuration but are not present in the state or real infrastructure.
- **Destroy resources** that exist in the state but are no longer defined in the configuration.
- **Update resources in-place** when only modifiable attributes have changed.
- **Destroy and recreate resources** when changes cannot be applied in-place due to provider/API limitations.
### Understanding the Limitations

- Terraform strictly follows the **configuration as the source of truth**.
- If changes are made **outside Terraform (manual changes in cloud)**, Terraform will try to **revert them** during `apply`.
### Changing Default Behavior

- You can control this using the **`lifecycle` block**.
Example (ignore external changes):
```
lifecycle {  
  ignore_changes = [tags]  
}
```
- This tells Terraform to **ignore specific attribute changes**, even if they differ from the configuration.
---
### 🔹 In-place vs Replacement

|Type|Behavior|
|---|---|
|In-place update|Resource modified without recreation|
|Replacement|Resource destroyed and recreated|

Example:

- Changing `instance_type` → in-place
    
- Changing `AMI` → replacement
    

---

### 🔹 Preventing Accidental Deletion

```
lifecycle {  
  prevent_destroy = true  
}
```

- Terraform will **throw an error instead of deleting the resource**.
    

---

### 🔹 Ignoring Changes

```
lifecycle {  
  ignore_changes = [tags]  
}
```

- Useful when external systems modify attributes (like tags).
    

---

|Meta-Argument|Description|
|---|---|
|depends_on|Handles hidden resource or module dependencies that Terraform cannot automatically infer.|
|count|Accepts a whole number and creates that many instances of the resource.|
|for_each|Accepts a map or set of strings and creates an instance for each item.|
|lifecycle|Controls resource lifecycle behavior (e.g., prevent destroy, ignore changes, create before destroy).|
|provider|Specifies which provider configuration to use for a resource.|
|provisioner|Used to execute scripts or commands on a resource after creation (not recommended for most production use cases).|

### Must-Know Insight
- **Most commonly used in real-world:**
    - `count`
    - `for_each`
    - `lifecycle`
    - `depends_on`
- **Less commonly used (but important):**
    - `provider` (multi-region/multi-account setups)
    - `provisioner` (edge cases, avoid if possible)
---

## Must-Know Points
- Meta arguments **control how Terraform behaves**, not what it creates.
- `count` and `for_each` are used for **scaling resources**.
- `depends_on` is for **explicit dependencies**.
- `lifecycle` is critical for **production safety and zero downtime**.
- Not all meta arguments apply to every resource, but most are widely supported.

---

### Simple Model

Resource → WHAT to create  
Meta Arguments → HOW to create/manage it
