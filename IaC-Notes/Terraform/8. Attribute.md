- Each resource in Terraform has its own set of attributes.
- Attributes are the fields inside a resource block that hold values describing the resource configuration.
- These values are stored in the Terraform **state file** after the resource is created or updated.
- Attributes can either be:
    - **Arguments** → values we define in configuration
    - **Computed attributes** → values generated by the provider after resource creation (e.g., IDs, IPs)

```hcl
resource "aws_instance" "web" {
	ami           = "ami-123456"
	instance_type = "t2.micro"
}
```

In this example:

- `ami` and `instance_type` are attributes.

### Cross-Resource Attribute Reference

Terraform allows one resource to reference attributes from another resource.

This enables **resource dependency and dynamic configuration**.

Example:

```hcl
resource "aws_instance" "web" {
	vpc_security_group_ids = [aws_security_group.web_sg.id]
}
```

Here:

- `aws_security_group.web_sg.id` references the **id attribute** of the security group resource.

### Why This Matters

Cross-resource references allow Terraform to:

- automatically determine **resource dependencies**
- create resources in the **correct order**
- dynamically pass values between resources

Example dependency flow:

Elastic IP → Security Group → EC2 Instance

If a referenced attribute changes, Terraform will detect it during `terraform plan` and update dependent resources accordingly.

### Commonly Referenced Attributes

Some attributes are frequently referenced across resources:

|Attribute|Purpose|
|---|---|
|`id`|Unique identifier of the resource|
|`arn`|AWS resource identifier|
|`public_ip`|Public IP address|
|`private_ip`|Internal IP inside the VPC|
|`dns_name`|DNS endpoint for services like load balancers|

Example:

`cidr_ipv4 = "${aws_eip.lb.public_ip}/32"`
