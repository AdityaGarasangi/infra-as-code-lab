- **Data sources allow Terraform to read information from existing infrastructure instead of creating new resources.**
- They are used when you need to **fetch details about already existing resources** such as:
    - existing VPC
    - existing AMI
    - existing subnet
    - existing security group
    - existing IAM roles
- Terraform **does not manage or modify these resources**, it only **retrieves their data for use in configuration**.

---

- Syntax of a data source:

```
data "<PROVIDER>_<RESOURCE_TYPE>" "<NAME>" {
  configuration
}
```

Example:

```
data "aws_vpc" "main" {
  id = "vpc-12345"
}
```

Accessing its value:

```
data.aws_vpc.main.cidr_block
```

---

- Difference between **resource and data source**

|Type|Purpose|
|---|---|
|resource|Creates and manages infrastructure|
|data source|Reads information from existing infrastructure|

Example:

Create new resource:

```
resource "aws_instance" "web" {
  ami           = "ami-123"
  instance_type = "t3.micro"
}
```

Read existing resource:

```
data "aws_ami" "ubuntu" {
  most_recent = true
}
```

---

- Data sources are referenced using:

```
data.<provider>_<type>.<name>.<attribute>
```

Example:

```
data.aws_ami.ubuntu.id
```

## Common Terraform Data Sources (AWS)

### Fetch Latest AMI

Instead of hardcoding AMI IDs (which change often), you can dynamically fetch the latest image.

Example:

```
data "aws_ami" "ubuntu" {
  most_recent = true

  owners = ["amazon"]

  filter {
    name   = "name"
    values = ["ubuntu/images/hvm-ssd/ubuntu-jammy-22.04-amd64-server-*"]
  }
}
```

Usage:

```
resource "aws_instance" "web" {
  ami           = data.aws_ami.ubuntu.id
  instance_type = "t3.micro"
}
```

Terraform will automatically fetch the **latest Ubuntu AMI**.

---

### Fetch Existing VPC

Example:

```
data "aws_vpc" "main" {
  id = "vpc-12345"
}
```

Usage:

```
cidr_block = data.aws_vpc.main.cidr_block
```

---

### Fetch Existing Subnet

Example:

```
data "aws_subnet" "private" {
  id = "subnet-abc123"
}
```

Usage:

```
subnet_id = data.aws_subnet.private.id
```

---

### Fetch Availability Zones

Useful when creating resources across multiple AZs.

Example:

```
data "aws_availability_zones" "available" {}
```

Usage:

```
data.aws_availability_zones.available.names
```

Result example:

```
[
  "us-east-1a",
  "us-east-1b",
  "us-east-1c"
]
```

---

## Real Production Example

Dynamic subnet distribution across AZs:

```
data "aws_availability_zones" "available" {}
```

```
resource "aws_subnet" "public" {
  count = 2

  availability_zone = data.aws_availability_zones.available.names[count.index]
}
```

Terraform automatically spreads resources across AZs.

---

## Filtering in Data Sources

Data sources often support **filters** to narrow down results.

Example:

```
data "aws_security_group" "web" {
  filter {
    name   = "group-name"
    values = ["web-sg"]
  }
}
```

---

## Using Data Source With Modules

Modules often require existing resources.

Example:

```
data "aws_vpc" "main" {
  id = var.vpc_id
}
```

Then passed to module:

```
module "network" {
  source = "../../modules/network"

  vpc_id = data.aws_vpc.main.id
}
```

## Common Real-World Use Cases

Data sources are heavily used in production for:

|Scenario|Example|
|---|---|
|Fetch latest AMI|aws_ami|
|Use existing VPC|aws_vpc|
|Fetch subnet IDs|aws_subnet|

|Use existing IAM role|aws_iam_role|
|Fetch existing security group|aws_security_group|

---

## Important Behavior

- Data sources **do not create infrastructure**
- They **only fetch information**
- Terraform refreshes data sources during **plan**
- If the referenced resource **does not exist, Terraform fails**

---

## Example Full Flow

```
data "aws_ami" "ubuntu" {
  most_recent = true
  owners      = ["amazon"]
}
```

```
resource "aws_instance" "web" {
  ami           = data.aws_ami.ubuntu.id
  instance_type = "t3.micro"
}
```

Flow:

```
Terraform → Queries AWS → Finds latest AMI → Uses it to launch EC2
```

---

## Important Points to Remember

- `data` keyword is used to define data sources.
- Used to **fetch existing infrastructure information**.
- Cannot modify or manage those resources.
- Frequently used with **AMI lookup, VPC lookup, subnet lookup, and AZ discovery**.
- Data source values are referenced using:
```
data.<type>.<name>.<attribute>
```
