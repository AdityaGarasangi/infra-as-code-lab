- Output values expose information about the infrastructure after Terraform creates or updates resources.
- They are displayed in the terminal after `terraform apply`.
- Outputs can also be used by other Terraform modules or external systems.
- You can output a specific attribute of a resource

```hcl
#only public ip will be exposed in a formatted URL
output "public-ip" {
	value = "<https://$>{aws_eip.tf_lb.public_ip}:8000"
}

#output
public-ip = <https://34.203.11.10:8000>
```

- You can expose the entire resource object.

`Note: This is usually avoided in production because it exposes **too much information**`

```hcl
#All attributes of aws_eip.lb will be exposed
output "public-ip" {
	value = aws_eip.tf_lb
}
```

- This returns all attributes Terraform knows about that resource (ID, public IP, private IP, ARN, etc.).
- Common Uses of Outputs
    - Display important information after deployment (IP addresses, DNS names, IDs).
    - Pass values **from child modules to the root module**.
    - Provide infrastructure data to **external tools or scripts**.
    - Share resource attributes between Terraform configurations.
- Sensitive Outputs
    - If the output contains secrets (passwords, tokens, keys), mark it as sensitive. Terraform will hide it from CLI output.

```hcl
output "db_password" {
  value     = aws_db_instance.main.password
  sensitive = true
}
```

- Accessing Output Values
    
    - After running `terraform apply`, you can retrieve outputs using
    
    ```hcl
    #All Outputs
    terraform output
    
    #Specific Output
    terrafor output public-ip
    
    #JSON Format
    terraform output -json
    ```
    
- Best Practices
    
    - Output only **useful values** (IPs, DNS names, IDs).
    - Avoid exposing sensitive data unless necessary.
    - Use clear output names for readability.
    - Use outputs to connect **modules together**.
