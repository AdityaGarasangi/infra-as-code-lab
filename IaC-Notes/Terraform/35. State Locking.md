## What is State Locking?

**State locking** prevents multiple users or processes from **modifying the Terraform state at the same time**.

When Terraform runs an operation like `apply`, it **locks the state file** so others cannot make changes until the operation finishes.

---

# Why State Locking is Important

Without state locking:

- Two engineers could run `terraform apply` simultaneously.
- Both modify the same state file.
- This can lead to **state corruption or inconsistent infrastructure**.

State locking ensures **safe concurrent usage in team environments**.

# How State Locking Works

1. Terraform starts an operation (`plan`, `apply`, etc.).
2. Terraform **acquires a lock on the state file**.
3. Other Terraform operations must **wait until the lock is released**.
4. After the operation finishes, the **lock is removed**.

---

# Backends That Support Locking

|Backend|Locking Support|
|---|---|
|S3 + DynamoDB|Yes|
|Terraform Cloud|Yes|
|Azure Storage|Yes|
|Google Cloud Storage|Yes|
|Local backend|No|

Example (AWS):

- **S3** → stores state
- **DynamoDB** → manages lock

---

# Example Configuration

```
terraform {  
  backend "s3" {  
    bucket         = "terraform-state-bucket"  
    key            = "prod/terraform.tfstate"  
    region         = "us-east-1"  
    dynamodb_table = "terraform-lock-table"  
  }  
}
```
Here:

- DynamoDB table is used to **create and manage state locks**.

---

# Force Unlock (If Lock Gets Stuck)

Sometimes Terraform crashes and leaves the state locked.

You can manually unlock it:

terraform force-unlock LOCK_ID

Example:

terraform force-unlock 12345678-abcd

⚠️ Use carefully — only when you are sure no Terraform operation is running.

---

# Important Points

- Prevents **simultaneous state modification**.
- Critical for **team collaboration**.
- Supported only by **remote backends**.
- Protects against **state corruption**.
