- In Terraform, a firewall for EC2 instances is managed using **Security Groups**.
    
    You typically need **3 resource blocks**:
    
    1. `aws_security_group`
        
        This defines the security group itself.
        
        It allows you to specify:
        
        - `name`
        - `description`
        - `vpc_id` (the VPC where the security group belongs)
        
        ```
        resource "aws_security_group" "example" {
          name        = "example-sg"
          description = "Security group for EC2 instance"
          vpc_id      = var.vpc_id
        }
        ```
        
    2. `aws_security_group_ingress_rule`
        
        Defines **inbound rules**
        
        (Traffic allowed _to_ the EC2 instance)
        
        You specify:
        
        - `from_port`
        - `to_port`
        - `ip_protocol`
        - `cidr_ipv4` (or security group reference)
        - `security_group_id`
    
    ```
    resource "aws_security_group_ingress_rule" "http" {
      security_group_id = aws_security_group.example.id
      from_port         = 80
      to_port           = 80
      ip_protocol       = "tcp"
      cidr_ipv4         = "0.0.0.0/0"
    }
    ```
    
    1. `aws_security_group_egress_rule`
        
        Defines **outbound rules**
        
        (Traffic allowed _from_ the EC2 instance)
        
    
    ```
    resource "aws_security_group_egress_rule" "all_outbound" {
      security_group_id = aws_security_group.example.id
      ip_protocol       = "-1"
      cidr_ipv4         = "0.0.0.0/0"
    }
    ```
    
- AWS Has Default Outbound Allow-All
    
    - If you don’t define egress rules, AWS allows all outbound traffic by default.
        
        If you want strict control:
        
        - Explicitly define egress rules
        - Remove default behavior
- Avoid Inline Rules (Production Best Practice)
    
- Instead of:
    

```
resource "aws_security_group" "example" {
  ingress { ... }
  egress  { ... }
}
```

Use **separate rule resources** like:

- `aws_security_group_ingress_rule`
- `aws_security_group_egress_rule`

Why?

1. Prevents rule replacement issues
2. Better lifecycle control
3. Avoids Terraform diff chaos
4. More modular

This is the modern recommended approach.

- Don’t Use `0.0.0.0/0` Carelessly
    
    Yes, it’s easy.
    
    But:
    
    - SSH (22) should NOT be open to the world
    - Database ports (3306, 5432) should NOT be public
    - Use specific CIDRs or reference another security group
- Use Variables (Never Hardcode in Real Projects)
    
- Security Groups Are Stateful
    
    This is big.
    
    If inbound is allowed, response traffic is automatically allowed.
    
    Unlike NACLs:
    
    - No need to open ephemeral ports manually.
```
#firewall.tf
resource "aws_security_group" "tf_firewall" {
  name        = "tf_firewall"
  description = "This firewall is managed by Terraform"
  # vpc_id      = var.vpc_id
}

resource "aws_vpc_security_group_ingress_rule" "allow_http_ipv4" {
  security_group_id = aws_security_group.tf_firewall.id

  ip_protocol = "tcp"
  from_port   = 8080
  to_port     = 8089
  cidr_ipv4   = "0.0.0.0/0"

  description = "Allow HTTP from anywhere"
}

resource "aws_vpc_security_group_egress_rule" "allow_all_traffic_ipv4" {
  security_group_id = aws_security_group.tf_firewall.id

  ip_protocol = "-1" # "-1" means all protocols
  from_port   = 0
  to_port     = 0
  cidr_ipv4   = "0.0.0.0/0"

  description = "Allow all outbound traffic"
}
```

### Elastic IP

- Elastic IP is static IPv4 address in AWS
- User can create it and associate it with EC2 instance
```
#eip.tf
resource "aws_eip" "tf_lb" { 
	 domain = "vpc"
}

resource "aws_eip_association" "tf_lb_assoc" {
	  instance_id   = aws_instance.my_ec2.id
	  allocation_id = aws_eip.tf_lb.id
}
```
