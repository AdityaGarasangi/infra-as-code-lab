## What is Dependency Lock File?

The **dependency lock file** (`.terraform.lock.hcl`) is used to **lock provider versions** so Terraform installs the **same versions every time**.

This ensures **consistent and reproducible infrastructure deployments**.

---

## File Name

`.terraform.lock.hcl`

Automatically created when you run:

```
terraform init
```

---

## Why It Is Important

Without a lock file:

- Different team members may use **different provider versions**
- Leads to **unexpected behavior or failures**

With lock file:

- Same provider versions across:
    - Developers
    - CI/CD pipelines
    - Environments

---

## Example Content

```
provider "registry.terraform.io/hashicorp/aws" {  
  version = "5.0.0"  
  hashes = [  
    "h1:abc123...",  
    "zh:xyz456..."  
  ]  
}
```
---

## What It Stores

- Provider versions
- Provider source
- Hashes (for integrity verification)

---

## How It Works

1. `terraform init` downloads providers
2. Writes versions to `.terraform.lock.hcl`
3. Future runs use the **same locked versions**

---

## Updating Providers

To upgrade providers:

`terraform init -upgrade
`
This updates the **lock file with newer versions**.

---

## Important Points

- Should be **committed to Git** ✅
- Ensures **team consistency**
- Works only for **providers (not modules)**
- Prevents **unexpected upgrades**

---

## Lock File vs Version Constraints

|Feature|Version Constraint|Lock File|
|---|---|---|
|Defined In|`.tf` file|`.terraform.lock.hcl`|
|Purpose|Set allowed versions|Lock exact version|
|Flexibility|Flexible|Fixed|

---

## Quick Summary

- Locks **exact provider versions**
- Created during **`terraform init`**
- Ensures **consistent environments**
- Must be **committed to version control**
