## Not recommended to use this command

- When ever there is changes in Current state compared to desired state , we can use `terraform refresh` or `terraform apply -refresh-only` to let it check the latest state of infra and update `.tfstate` file accordingly
    
- If you refresh your state but don't update your code, you haven't actually fixed the drift; you've just made Terraform aware of it. The next time you run a regular `terraform apply`, Terraform will see that your code is still "blank" (requesting defaults) and will try to **undo** your manual changes to get back to those original defaults.
    
- **_Terraform explicitly use_ refresh command _for every_ terraform plan _or_ terraform apply _command_**
    
- refresh will not fix the drift, it will only update state file
    
- since `plan` does refresh anyways, So use `apply -refresh-only` when i want to update state file and not try to revert or change anything
    
    - this allows you to see exactly what changed in the console so you can copy those values into your code **before** you run a real `apply`
- _**The "Adopt-and-Sync" Workflow**_ ➖***(Best Approach If using terraform refresh)***
    
    If manually changed something in the console and want it to stay that way →
    
    1. **Run `terraform apply -refresh-only`**
        - **What it does:** Updates your `.tfstate` file to match the actual AWS Console.
        - **Why:** It makes the "invisible" manual change visible to Terraform's memory.
        - _Note: `terraform refresh` is deprecated; `refresh-only` is the safer, modern version._
    2. **Inspect the Output**
        - Terraform will show you exactly what changed (e.g., `+ vpc_security_group_ids = ["sg-012345"]`).
    3. **Update your Code (`.tf` files)**
        - Manually type that security group ID (or whatever you changed) into your resource block.
        - If you don't do this, the next `plan` will show: `~ vpc_security_group_ids = ["sg-012345"] -> (default)`.
    4. **Run `terraform plan`**
        - If you did it correctly, Terraform should now say: **"No changes. Your infrastructure matches the configuration."**
