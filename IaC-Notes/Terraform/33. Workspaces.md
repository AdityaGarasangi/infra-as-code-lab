## What is a Workspace?

A **Terraform workspace** allows you to manage **multiple instances of the same infrastructure configuration** using **different state files**.

Each workspace maintains its **own Terraform state**, enabling environments like:

- **dev**
- **staging**
- **prod**

while using the **same Terraform code**.

---

# Default Workspace

When you initialize Terraform, it automatically creates a workspace called:

default

This is the workspace Terraform uses unless you switch to another one.

---

# Why Workspaces are Used

Workspaces are useful for managing **multiple environments without duplicating code**.

Example:

Same configuration but different infrastructure:

|Workspace|Infrastructure|
|---|---|
|dev|Small resources|
|staging|Medium resources|
|prod|Production-grade resources|

---

# Workspace Commands

## List Workspaces

terraform workspace list

Example output:

* default  
  dev  
  prod

`*` indicates the **current workspace**.

---

## Create Workspace

```
terraform workspace new dev
```

Creates a **new workspace with its own state file**.

---

## Switch Workspace

```
terraform workspace select dev
```

Switches Terraform to the **dev environment**.

---

## Show Current Workspace

```
terraform workspace show
```

Displays the **active workspace**.

---

## Delete Workspace

```
terraform workspace delete dev
```

Removes the workspace.

---

# Using Workspace in Code

Terraform provides a built-in variable:

```
terraform.workspace
```

Example:

```
resource "aws_instance" "app" {  
  instance_type = terraform.workspace == "prod" ? "t3.medium" : "t2.micro"  
}
```

Here:

- **prod workspace → larger instance**
- **other workspaces → smaller instance**

---

# State File Behavior

Each workspace has a **separate state file**.

Example structure:

```
terraform.tfstate.d/  
   dev/  
      terraform.tfstate  
   prod/  
      terraform.tfstate
```

---

# Important Points

- Workspaces allow **environment isolation**.
- Each workspace has its **own state file**.
- Same Terraform configuration is reused across environments.
- Useful for **dev/staging/prod setups**.

---

# Limitations of Workspaces

Workspaces are **not ideal for large production environments** because:

- All environments share the **same codebase**.
- Harder to manage **complex infrastructure differences**.

In real-world setups, teams often prefer:

- **Separate directories**
- **Separate Terraform projects**
- **Separate state backends**
