## What is a `removed` Block?

A **`removed` block** tells Terraform that a **resource should be removed from the state** (and optionally destroyed in real infrastructure).

It is mainly used during **refactoring or cleanup** of Terraform configurations.

---

## Basic Syntax

```
removed {  
  from = aws_instance.old_resource  
}
```

---

## Example

Suppose you delete a resource from your code but want to handle it safely:

```
removed {  
  from = aws_instance.web  
}
```

Terraform understands that:

- This resource is **intentionally removed**
- It should be **handled properly during apply**

---

## With Lifecycle Option

You can control whether the actual infrastructure is destroyed:

```
removed {  
  from = aws_instance.web  
  
  lifecycle {  
    destroy = true  
  }  
}
```
### Behavior

|Option|Result|
|---|---|
|`destroy = true`|Resource is destroyed + removed from state|
|`destroy = false`|Only removed from state (infra remains)|

---

## When to Use

- Removing resources during **refactoring**
- Cleaning up **unused infrastructure**
- Safely handling **state transitions**

---

## Important Points

- Helps Terraform understand **intentional removal**.
- Prevents unexpected behavior during `apply`.
- Works at the **state level**.
- Useful with **moved blocks during refactoring**.

---
## `removed` vs `terraform state rm`

|Feature|`removed` Block|`terraform state rm`|
|---|---|---|
|Type|Declarative (in code)|CLI command|
|Use Case|Planned refactoring|Manual state change|
|Tracking|Version-controlled|Not tracked in code|

---

## Quick Summary

- **`removed` block manages resource removal declaratively**
- Can **destroy resource or just remove from state**
- Useful for **clean and safe Terraform refactoring**
