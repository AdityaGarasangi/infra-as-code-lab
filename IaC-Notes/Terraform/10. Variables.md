- Terraform variables are used to **parameterize infrastructure configuration**, allowing values to be reused and changed easily without modifying core resource definitions.
- Variables help **avoid hardcoding values** in Terraform code, making the configuration cleaner, more maintainable, and easier to reuse across different environments.

Example:

```
variable "instance_type" {
  default = "t3.micro"
}

resource "aws_instance" "web" {
  instance_type = var.instance_type
}
```

- Variables allow updating values **from one central place instead of editing multiple resources**, reducing manual work and avoiding human errors.
- Variables are typically declared inside a **`variables.tf` file**, but they can technically exist in **any `.tf` file within the same directory** since Terraform loads all `.tf` files in a folder together.

Basic declaration syntax:

```
variable "app_port" {
  default = 8080
}
```

Using the variable:

```
from_port = var.app_port
to_port   = var.app_port
```

- Variables can include additional arguments such as **type, description, default value, and sensitivity** to improve validation and readability.

Example with type and description:

```
variable "ssh_port" {
  description = "Port used for SSH access"
  type        = number
  default     = 22
}
```

- Common variable types supported by Terraform:

|Type|Example|
|---|---|
|string|`"us-east-1"`|
|number|`8080`|
|bool|`true`|
|list|`["subnet-a", "subnet-b"]`|
|map|`{env = "prod"}`|
|object|structured values|

Example list variable:

```
variable "availability_zones" {
  type = list(string)
}
```

- Variables are referenced using the **`var.<variable_name>` syntax**.

Example:

```
cidr_ipv4 = var.vpn_static_ip
```

- Terraform variables follow a **priority order when assigning values**. If multiple sources provide values, Terraform uses the highest priority.

### Terraform Variable Definition File (`.tfvars`)

- A **`.tfvars` file** is used to **assign values to variables separately from the main Terraform code**.
- This helps keep infrastructure code **clean and environment-independent**, while allowing different values for different deployments.

Example variable declaration:

```
variable "app_port" {
  type = number
}
```

Example `terraform.tfvars` file:

```
app_port = 8080
vpn_static_ip = "141.35.126.158/32"
```

- Terraform automatically loads the following variable files:

```
terraform.tfvars
terraform.tfvars.json
*.auto.tfvars
```

- `.tfvars` files are commonly used to **define environment-specific values**, such as dev, staging, or prod configurations.

Example:

```
dev.tfvars
prod.tfvars
```

`Run Terraform with a specific variable file:`

```
terraform apply-var-file="prod.tfvars"
```

- Variables defined in `.tfvars` **override the default values defined inside the variable block**.

Example:

```
variable "app_port" {
  default = 8080
}
```

If `terraform.tfvars` contains:

```
app_port = 9000
```

Terraform will use **9000 instead of 8080**.

### Variable Value Priority

1. CLI Flag → `terraform apply -var="app_port=9000"`
2. `.tfvars` files
3. Environment variables → `TF_VAR_app_port=9000`
4. Default values inside variable block in `variables.tf`

# Variable Definition Precedence

Terraform can receive variable values from **multiple places**, so it needs a clear rule to decide **which value wins** if the same variable is defined in several locations. This is called **variable precedence**.

Think of it like a priority ladder — **the highest priority value overrides everything below it**.

Terraform checks variable values in this order (highest → lowest priority):

1️⃣ **Command line `-var` flag**

```hcl
terraform apply-var="instance_type=t3.large"
```

Example:

`variables.tf`

```
variable "instance_type" {
  default = "t3.micro"
}
```

`terraform.tfvars`

```
instance_type = "t3.small"
```

Command:

```
terraform apply-var="instance_type=t3.large"
```

Result Terraform uses:

```
instance_type = t3.large
```

The CLI value overrides **everything else**.

---

2️⃣ **Command line `-var-file`**

You can explicitly pass a variables file.

Example:

```
terraform apply-var-file="prod.tfvars"
```

Example file:

`prod.tfvars`

```
instance_type = "t3.medium"
```

If both exist:

```
terraform.tfvars → t3.small
prod.tfvars → t3.medium
```

and you run:

```
terraform apply-var-file="prod.tfvars"
```

Terraform uses:

```
t3.medium
```

---

3️⃣ **Automatic variable files (`*.auto.tfvars`)**

Terraform automatically loads any file ending with:

```
*.auto.tfvars
*.auto.tfvars.json
```

Example:

```
dev.auto.tfvars
network.auto.tfvars
```

Example:

`dev.auto.tfvars`

```
environment = "dev"
```

These are **automatically applied without needing `-var-file`**.

---

4️⃣ **`terraform.tfvars`**

Terraform automatically loads this file if it exists.

Example:

`terraform.tfvars`

```
instance_type = "t3.small"
app_port      = 8080
```

This is the **most common file for assigning variables**.

---

5️⃣ **Environment variables**

Terraform can read variables from environment variables using the prefix:

```
TF_VAR_
```

Example:

```
exportTF_VAR_instance_type="t3.micro"
```

Terraform maps it to:

```
var.instance_type
```

This is commonly used in **CI/CD pipelines**.

Example:

```
TF_VAR_region=us-east-1
TF_VAR_instance_type=t3.medium
```

---

6️⃣ **Default value in `variables.tf` (lowest priority)**

Example:

```
variable "instance_type" {
  type    = string
  default = "t3.micro"
}
```

Terraform will only use this if **no other source provides a value**.

---

## Full Precedence Order (Highest → Lowest)

```
1. -var flag
2. -var-file
3. *.auto.tfvars
4. terraform.tfvars
5. TF_VAR_ environment variables
6. default value in variable block
```

---

## Full Example

`variables.tf`

```
variable "instance_type" {
  default = "t3.micro"
}
```

`terraform.tfvars`

```
instance_type = "t3.small"
```

Environment variable:

```
exportTF_VAR_instance_type="t3.medium"
```

Command:

```
terraform apply-var="instance_type=t3.large"
```

Terraform evaluates:

```
default value → t3.micro
terraform.tfvars → t3.small
environment variable → t3.medium
CLI var → t3.large
```

Final value used:

```
t3.large
```

---

## Important Behavior

If a variable **has no default and no value anywhere**, Terraform will prompt:

```
var.instance_type
Enter a value:
```

Example variable:

```
variable "instance_type" {
  type = string
}
```

---

## Practical DevOps Usage

In real projects the typical pattern is:

```
variables.tf      → define variables
dev.tfvars        → dev values
prod.tfvars       → prod values
CI/CD pipeline    → override sensitive values
```

Example deployment:

```
terraform apply -var-file="prod.tfvars"
```


**Simple way to remember precedence**
```
CLI overrides everything
Files override defaults
Defaults are fallback
```
