- Terraform debugging helps identify **why a configuration fails during `init`, `plan`, or `apply`**.
- The most important debugging tool in Terraform is **logging**.

---

- Terraform supports different **log levels** through the environment variable `TF_LOG`.

Basic syntax:

```
TF_LOG=<LEVEL> terraform <command>
```

Example:

```
TF_LOG=DEBUG terraform apply
```

This prints detailed internal logs that help diagnose problems.

---

- Common Terraform log levels:

|Level|Purpose|
|---|---|
|TRACE|Extremely detailed internal logs|
|DEBUG|Detailed debugging information|
|INFO|General informational logs|
|WARN|Warnings|
|ERROR|Only errors|

Example:

```
TF_LOG=TRACE terraform plan
```

---

- Logs can also be written to a **file instead of terminal**.

Example:

```
exportTF_LOG=DEBUG
exportTF_LOG_PATH=terraform.log

terraform apply
```

Terraform will store logs in:

```
terraform.log
```

---

- Use **`terraform validate`** to detect syntax and configuration errors before running a plan.

Example:

```
terraform validate
```

This checks:

- syntax errors
- missing variables
- incorrect block structure

---

- Use **`terraform plan`** to debug infrastructure changes before applying them.

Example:

```
terraform plan
```

This shows:

- what resources will be created
- modified
- destroyed

It helps catch mistakes before `apply`.

---

- Use **`terraform console`** to test expressions and variable values interactively.

Example:

```
terraform console
```

Example test:

```
> var.app_port
8080

> upper("dev")
"DEV"
```

Useful for debugging:

- functions
- locals
- variable values

---

- If Terraform behaves unexpectedly, refresh state using:

```
terraform refresh
```

This syncs Terraform state with real infrastructure.

---

- To check Terraform state values:

```
terraform state list
```

Shows all resources in state.

Example:

```
aws_instance.web
aws_security_group.tf_firewall
```

---

- Inspect a specific resource in state:

```
terraform state show aws_instance.web
```

This helps verify actual stored attributes.

---

- If a resource becomes inconsistent, Terraform allows **tainting**.

Example:

```
terraform taint aws_instance.web
```

Terraform will **force recreation** of that resource on next apply.

---

### Quick Must-Know Commands

|Command|Purpose|
|---|---|
|`terraform validate`|Validate configuration|
|`terraform plan`|Preview infrastructure changes|
|`terraform console`|Test expressions and variables|
|`terraform state list`|Show resources in state|
|`terraform state show`|Inspect resource attributes|
|`TF_LOG=DEBUG terraform apply`|Enable debugging logs|
