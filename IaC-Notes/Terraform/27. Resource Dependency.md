## What is Resource Dependency?

Resource dependency in Terraform defines the **order in which resources are created, updated, or destroyed**.

Terraform builds a **dependency graph** and ensures resources are processed in the correct sequence.

---

## Types of Dependencies

### 1. Implicit Dependency (Most Common)

Terraform automatically detects dependencies when one resource references another.

### Example:

```
resource "aws_vpc" "main" {  
  cidr_block = "10.0.0.0/16"  
}  
  
resource "aws_subnet" "subnet1" {  
  vpc_id = aws_vpc.main.id  
  cidr_block = "10.0.1.0/24"  
}
```

### How it works:

- `aws_subnet.subnet1` depends on `aws_vpc.main`
- Because it uses: `aws_vpc.main.id`

Terraform automatically creates VPC first, then subnet.

---

### 2. Explicit Dependency (`depends_on`)

Used when Terraform **cannot automatically detect dependency**.

### Example:
```
resource "aws_instance" "app" {  
  ami           = "ami-123456"  
  instance_type = "t2.micro"  
  
  depends_on = [aws_security_group.sg]  
}  
  
resource "aws_security_group" "sg" {  
  name = "app-sg"  
}
```

### When to use:

- No direct reference exists
- Hidden dependencies (like scripts, provisioners, external setup)
---

## Important Points

### 1. Terraform uses a Dependency Graph

- Builds a **DAG (Directed Acyclic Graph)**
- Executes resources in parallel wherever possible

---

### 2. Avoid Overusing `depends_on`

- Makes execution slower
- Breaks Terraform’s ability to parallelize  

Use only when necessary

---

### 3. Implicit > Explicit

- Always prefer **implicit dependencies**
- Cleaner and less error-prone

---

### 4. Applies to More Than Resources

Dependencies also work with:
- `modules`
- `data sources`
- `outputs`

---

## Example with Hidden Dependency

```
resource "null_resource" "setup" {  
  provisioner "local-exec" {  
    command = "echo setup done"  
  }  
}  
  
resource "aws_instance" "app" {  
  ami           = "ami-123456"  
  instance_type = "t2.micro"  
  
  depends_on = [null_resource.setup]  
}
```

No direct reference, so we force dependency.

---

## Quick Summary

| Type     | How it Works    | Use Case                   |
| -------- | --------------- | -------------------------- |
| Implicit | Reference-based | Default & preferred        |
| Explicit | `depends_on`    | Hidden/manual dependencies |
