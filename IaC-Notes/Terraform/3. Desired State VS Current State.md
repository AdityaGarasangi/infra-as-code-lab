- Desired state is the configuration that is defined in `.tf` files
    
- Current State is the actual reality of infra that exists (_Terraform uses providers API to check current state of infra_)
    
- **The Reconciliation Process** ➖
    
    - When run **terraform plan** | **terraform apply,** Terraform first reaches out to AWS provider’s API to **check current state** of infra ****
    - Terraform will **compare current state against desired state**
    - Based on differences, Terraform determines what **actions are necessary to make the current state match the desired state**
    - Priority is to **match current state exactly same as desired state**

|              |                                          |
| :----------: | ---------------------------------------- |
|    Create    | If desired exists but current does not   |
|    Update    | if both exists but properties differs    |
|    Delete    | if current exists but in desired removed |
| No-operation | if current matches desired exactly       |

### `when ec2 is launched without specifying certain configurations, AWS automatically assigns default values to those unspecified settings`

- These default configurations are **not explicitly defined in the desired state (Terraform code)**.
    
- However, once the resource is created, Terraform **stores the actual resulting values (including defaults)** in the state file.
    
- So even if you didn’t define them, they can still exist in the Terraform state.
    
- If a default attribute is tracked in the Terraform state and AWS provider schema, and you manually modify it in the AWS Console, Terraform may detect drift.
    
- On the next `terraform plan`, Terraform may:
    
    - Revert it back
    - Or show a change
    - Or ignore it (depends on attribute behavior)
- It depends on whether the attribute is:
    
    - Computed
    - Optional
    - ForceNew
    - Ignored
- If an attribute was stored in the state (even if i never wrote it in code), and you change it manually in the AWS console:
    
    - Terraform may detect drift **if the provider includes that attribute in state refresh**.
        
    - It can show up in `terraform plan`.
        
        If Terraform sees the actual value doesn’t match the state, it may plan changes.
        
    
    But if the provider:
    
    - Does not expose that attribute in its schema,
        
    - Or treats it as non-tracked,
        
        then Terraform might not detect the manual change.
        
- **Best Approach** ➖Always explicitly define all desired attributes in `.tf` files
