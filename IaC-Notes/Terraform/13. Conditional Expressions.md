Syntax → `condition ? trueVal : falseVal`

- Conditional expressions allow Terraform configurations to **choose between two values based on a condition**.
- They are similar to **if–else logic** but written in a **single expression**.
- Syntax:

```
condition ? true_value : false_value
```

- If the **condition evaluates to true**, Terraform returns `true_value`.
- If the **condition evaluates to false**, Terraform returns `false_value`.

---

- Conditional expressions are commonly used with **variables to dynamically control infrastructure behavior**.

Example:

```
variable "environment" {
  default = "dev"
}
```

```
instance_type = var.environment == "prod" ? "t3.large" : "t3.micro"
```

Result:

```
environment = "prod" → t3.large
environment = "dev"  → t3.micro
```

---

- Conditional expressions are often used to **enable or disable resources with `count`**.

Example:

```
variable "create_instance" {
  type    = bool
  default = true
}
```

```
resource "aws_instance" "web" {
  count = var.create_instance ? 1 : 0

  ami           = "ami-123456"
  instance_type = "t3.micro"
}
```

Result:

```
true  → instance created
false → instance not created
```

---

- Conditional expressions can also be used to **set configuration values dynamically**.

Example:

```
variable "environment" {
  default = "dev"
}
```

```
variable "instance_count" {
  default = 1
}
```

```
count = var.environment == "prod" ? 3 : 1
```

Result:

```
prod → 3 instances
dev  → 1 instance
```

---

- Conditions often use **comparison operators**.

Common operators:

|Operator|Meaning|
|---|---|
|`==`|equal to|
|`!=`|not equal|
|`>`|greater than|
|`<`|less than|
|`>=`|greater than or equal|
|`<=`|less than or equal|

Example:

```
var.instance_count > 1 ? "multiple" : "single"
```

---

- Logical operators can also be used in conditions.

|Operator|Meaning|
|---|---|
|`&&`|AND|
|`||
|`!`|NOT|

Example:

```
(var.environment == "prod" && var.enable_monitoring) ? true : false
```

---

- Conditional expressions are commonly used for **environment-based configuration**.

Example:

```
variable "environment" {
  default = "dev"
}
```

```
tags = {
  Environment = var.environment == "prod" ? "Production" : "Development"
}
```

---

- Both `true_value` and `false_value` must return **compatible data types**.

Incorrect example:

```
var.environment == "prod" ? "t3.large" : 2
```

This fails because **string and number types do not match**.

Correct example:

```
var.environment == "prod" ? "t3.large" : "t3.micro"
```

---

- Conditional expressions can also return **complex values** such as lists or maps.

Example:

```
variable "environment" {
  default = "dev"
}
```

```
allowed_ips = var.environment == "prod" ? ["10.0.0.0/16"] : ["0.0.0.0/0"]
```

---

| Use Case                      | Example                     |
| ----------------------------- | --------------------------- |
| Environment-based configs     | dev vs prod settings        |
| Conditional resource creation | `count = condition ? 1 : 0` |
| Dynamic values                | instance type, ports        |
| Feature flags                 | enable/disable features     |
