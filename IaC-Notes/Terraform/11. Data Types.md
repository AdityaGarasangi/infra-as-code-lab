Terraform variables support several **data types** that define what kind of values a variable can accept. Using proper data types improves **validation, readability, and prevents configuration errors**.

---

- **string**

A `string` represents plain text values.

Commonly used for things like **regions, instance types, names, CIDR blocks, or IDs**.

Example:

```
variable "region" {
  type    = string
  default = "us-east-1"
}
```

Usage:

```
provider "aws" {
  region = var.region
}
```

Another example:

```
variable "vpn_static_ip" {
  type    = string
  default = "141.35.126.158/32"
}
```

---

- **number**

A `number` represents numeric values such as **ports, counts, or storage sizes**.

Example:

```
variable "app_port" {
  type    = number
  default = 8080
}
```

Usage example:

```
from_port = var.app_port
to_port   = var.app_port
```

Another common example:

```
variable "instance_count" {
  type    = number
  default = 2
}
```

Used in resources:

```
count = var.instance_count
```

---

- **bool**

A `bool` represents **true or false values**.

It is commonly used for enabling or disabling features.

Example:

```
variable "enable_monitoring" {
  type    = bool
  default = true
}
```

Usage example:

```
monitoring = var.enable_monitoring
```

Another example:

```
variable "create_nat_gateway" {
  type    = bool
  default = false
}
```

---

- **list**

A `list` represents an **ordered collection of values of the same type**.

Lists allow **duplicate values** and maintain order.

Example:

```
variable "availability_zones" {
  type = list(string)

  default = [
    "us-east-1a",
    "us-east-1b"
  ]
}
```

Usage example:

```
availability_zone = var.availability_zones[0]
```

Another common use case:

```
variable "allowed_ips" {
  type = list(string)

  default = [
    "141.35.126.158/32",
    "10.0.0.0/16"
  ]
}
```

Used in security group rules.

---

- **set**

A `set` is similar to a list but **does not allow duplicate values** and **does not maintain order**.

Terraform automatically removes duplicates.

Example:

```
variable "subnet_ids" {
  type = set(string)

  default = [
    "subnet-123",
    "subnet-456",
    "subnet-123"
  ]
}
```

Terraform will treat it as:

```
subnet-123
subnet-456
```

Typical use case: **IDs where duplicates should not exist**.

---

- **map**

A `map` represents **key-value pairs**, similar to a dictionary.

Commonly used for **tags, environment configurations, or grouped settings**.

Example:

```
variable "tags" {
  type = map(string)

  default = {
    Environment = "dev"
    Project     = "terraform-demo"
  }
}
```

Usage:

```
tags = var.tags
```

Another example:

```
variable "instance_types" {
  type = map(string)

  default = {
    dev  = "t3.micro"
    prod = "t3.large"
  }
}
```

Usage:

```
instance_type = var.instance_types["dev"]
```

---

- **null**

`null` represents **the absence of a value**.

When Terraform encounters `null`, it behaves as if the argument was **not defined at all**.

Example:

```
variable "key_name" {
  type    = string
  default = null
}
```

Usage:

```
key_name = var.key_name
```

If the value is `null`, Terraform **skips that argument when creating the resource**.

This is useful for **optional configurations**.

Example:

```
variable "ssh_key" {
  type    = string
  default = null
}
```

Then:

```
dev environment → ssh key used
prod environment → ssh key not required
```

---

- **Type Constraints**

Terraform allows you to enforce data types to **prevent incorrect values**.

Example:

```
variable "instance_type" {
  type = string
}
```

If someone provides a number instead of a string, Terraform will fail validation.

---

- **Complex Types**

Terraform also supports more complex structures like **objects and tuples**, which allow defining structured configurations.

Example:

```
variable "server_config" {
  type = object({
    instance_type = string
    volume_size   = number
  })
}
```

Example value:

```
server_config = {
  instance_type = "t3.micro"
  volume_size   = 20
}
```

---

|Data Type|Description|Example|
|---|---|---|
|string|Represents a sequence of characters (text). Used for values like names, regions, CIDR blocks, or instance types.|`"us-east-1"`|
|number|Represents numeric values. Used for ports, counts, storage sizes, or other numerical configurations.|`8080`|
|bool|Represents a boolean value: `true` or `false`. Used to enable or disable features or options.|`true`|
|list|An ordered collection of values of the same type. Allows duplicates and values can be accessed by index.|`["a","b"]`|
|set|An unordered collection of unique values of the same type. Duplicate values are automatically removed.|`["a","b"]`|
|map|A collection of key–value pairs where each key maps to a value. Commonly used for tags or configuration groups.|`{env="dev"}`|
|null|Represents the absence of a value. Terraform treats it as if the argument was not specified.|`null`|

|Concept|Description|
|---|---|
|Type Constraint|Used to restrict a variable to accept only a specific data type. This helps Terraform validate input values and prevents incorrect configurations. Example: `type = string`, `type = number`, `type = list(string)`.|
|object|A complex type that defines a structure with **named attributes**, where each attribute has its own data type. Used when grouping related configuration values together. Example: `{ instance_type = string, volume_size = number }`.|
|tuple|A complex type that defines a **fixed-length ordered list** where each element can have a different data type. Example: `[string, number, bool]` .|

---

- Common use cases for each data types
```
string → single values
number → ports / counts
bool → enable/disable flags
list → multiple ordered values
set → unique IDs
map → configuration groups or tags
null → optional parameters
```
