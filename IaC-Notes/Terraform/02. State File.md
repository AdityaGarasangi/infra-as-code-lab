- A **JSON file** that stores the current state of your infrastructure managed by Terraform.
- State file keeps track of resource created by _**terraform apply**_
- Keeps track of:
    - Resources created
    - Resource IDs
    - Metadata required for updates and deletes
- Stored locally in `terraform.tfstate` in the same folder as your `.tf` files
- **Not recommended for teams** — can lead to conflicts
- **Why Terraform Needs a State File?**
    - To map **Terraform resources → real infrastructure**.
    - To perform **incremental updates** instead of re-creating everything.
    - To **detect drift** (differences between code and actual infra).
- **Remote State**
    - Recommended for **team environments**.
    - Stored in a backend like:
        - **S3** (with DynamoDB for locking)
        - Azure Blob
        - GCP Storage
        - Terraform Cloud
    - Enables **collaboration** and prevents **concurrent modifications**.
- **State Locking**
    - Prevents two people from running `terraform apply` at the same time.
    - Example: S3 + DynamoDB lock table.
    - Avoids race conditions that could destroy or duplicate resources
- **Sensitive Data**
    - State can contain secrets like passwords, API keys, or database credentials.
    - Always **encrypt at rest** and **restrict access**.
    - Use `sensitive = true` in Terraform to prevent output from showing secrets in logs.
- **Workspace & Multiple Environments**
    - Each workspace has its own state file.
    - Common setup for `dev`, `stage`, `prod` environments.
    - Avoid manual duplication — use **remote state + workspace** or separate backends per environment
- **Backups**
    - Terraform creates `terraform.tfstate.backup` automatically.
    - Keep **versioned remote storage** to rollback if state gets corrupted.
- **State Operations**
    - `terraform state list` → lists all resources tracked in state
    - `terraform state show <resource>` → shows resource details
    - `terraform state rm <resource>` → removes a resource from state
    - `terraform import <resource>` → imports an existing resource into state
