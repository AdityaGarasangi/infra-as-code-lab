## What are Provisioners?

**Provisioners** are used to execute **scripts or commands on a resource after it is created or destroyed**.

They are typically used for **bootstrapping or configuring infrastructure**.

---

## Example

```
resource "aws_instance" "app" {  
  ami           = "ami-123456"  
  instance_type = "t2.micro"  
  
  provisioner "local-exec" {  
    command = "echo Instance created"  
  }  
}
```

---

## Common Types

|Provisioner|Description|
|---|---|
|`local-exec`|Runs commands on the machine running Terraform|
|`remote-exec`|Runs commands on the created resource via SSH/WinRM|
|`file`|Copies files from local machine to the resource|

---

## Important Points

- Run **after resource creation** by default.
    
- Can also run during **resource destruction**.
    
- Considered **last resort** in Terraform.
    
- Prefer **configuration management tools** or **cloud-init** instead.
    

---

## Quick Summary

Provisioners allow Terraform to **run scripts or commands during resource lifecycle**, mainly for **initial setup or configuration**.

---
Terraform provides several **built-in provisioners** used to run scripts or transfer files during the resource lifecycle.

---
# Types of Provisioners
## 1. `local-exec`

Runs a command **on the machine where Terraform is executed**.

### Example

```
provisioner "local-exec" {  
  command = "echo Instance created"  
}
```

**Use case:**  
Logging, triggering scripts, notifying external systems.

---

## 2. `remote-exec`

Runs commands **directly on the created resource** using **SSH or WinRM**.

### Example

provisioner "remote-exec" {  
```
  inline = [  
    "sudo apt update",  
    "sudo apt install nginx -y"  
  ]  
}
```
**Use case:**  
Initial configuration or software installation.

---

## 3. `file`

Used to **copy files from the local machine to the resource**.

### Example
```
provisioner "file" {  
  source      = "config.sh"  
  destination = "/tmp/config.sh"  
}
```
**Use case:**  
Uploading scripts, configuration files, or assets.

---
# Terraform Creation-Time and Destroy-Time Provisioners

Provisioners can run **during resource creation or destruction** depending on configuration.

---

## 1. Creation-Time Provisioner

Runs **after a resource is successfully created**.  
This is the **default behavior** for provisioners.

### Example

```
resource "aws_instance" "app" {  
  ami           = "ami-123456"  
  instance_type = "t2.micro"  
  
  provisioner "local-exec" {  
    command = "echo Instance created"  
  }  
}
```

Here, the command runs **after the instance is created**.

---

## 2. Destroy-Time Provisioner

Runs **before a resource is destroyed**.

To use it, set:

`when = destroy`

### Example

resource "aws_instance" "app" {  
  
```
  provisioner "local-exec" {  
    when    = destroy  
    command = "echo Instance is being destroyed"  
  }  
  
}
```

Here, the command runs **before Terraform deletes the resource**.
