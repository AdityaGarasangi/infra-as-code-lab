- Terraform console provides an interactive environment specifically designed to test function and experiment with expressions before integrating them into main code

Terraform functions are **built-in utilities that transform, calculate, or manipulate values inside Terraform expressions**. They help avoid complex manual logic by allowing you to **process data dynamically inside Terraform configurations**.

Functions are used with variables, resources, outputs, and expressions.

Basic syntax:

```
function_name(argument1, argument2, ...)
```

Example:

```
length(["a", "b", "c"])
```

Result:

```
3
```

Functions are evaluated during **terraform plan** and **terraform apply**, helping Terraform compute values before creating infrastructure.

---

## Why Terraform Functions Are Important

Functions are commonly used to:

- Transform variable values
- Process lists, maps, and strings
- Build dynamic resource configurations
- Extract specific elements from collections
- Perform calculations
- Format outputs
- Implement dynamic infrastructure logic

---

# String Functions

These functions work with **text values**.

### `lower()`

Converts a string to lowercase.

Example:

```
lower("DEV")
```

Result:

```
dev
```

Usage example:

```
tags = {
  environment = lower(var.environment)
}
```

---

### `upper()`

Converts a string to uppercase.

Example:

```
upper("dev")
```

Result:

```
DEV
```

---

### `title()`

Capitalizes the first letter of each word.

Example:

```
title("terraform infrastructure")
```

Result:

```
Terraform Infrastructure
```

---

### `replace()`

Replaces part of a string with another value.

Example:

```
replace("web-server", "-", "_")
```

Result:

```
web_server
```

---

### `trim()`

Removes characters from the beginning and end of a string.

Example:

```
trim("  hello  ", " ")
```

Result:

```
hello
```

---

### `format()`

Formats values into a string.

Example:

```
format("web-%d", 1)
```

Result:

```
web-1
```

Usage example:

```
tags = {
  Name = format("web-%d", count.index)
}
```

---

```
max(3, 7, 2)
```

```
7
```

```
min(3, 7, 2)
```

---

### `abs()`

```
abs(-10)
```

Result:

```
10
```

# Collection Functions

These functions operate on **lists, sets, and maps**.

### `length()`

Returns the number of elements in a collection.

Example:

```
length(["a", "b", "c"])
```

Result:

```
3
```

Example with variables:

```
count = length(var.subnet_ids)
```

---

### `element()`

Returns an element from a list using index.

Example:

```
element(["a", "b", "c"], 1)
```

Result:

```
b
```

---

### `contains()`

Checks if a collection contains a value.

Example:

```
contains(["dev", "prod"], "prod")
```

Result:

```
true
```

---

### `distinct()`

Removes duplicate values from a list.

Example:

```
distinct(["a", "b", "a"])
```

Result:

```
["a", "b"]
```

---

### `concat()`

Combines multiple lists.

Example:

```
concat(["a","b"],["c","d"])
```

Result:

```
["a","b","c","d"]
```

---

# Map Functions

Used for working with **key-value structures**.

### `keys()`

Returns all keys in a map.

Example:

```
keys({
  env = "dev"
  app = "web"
})
```

Result:

```
["env","app"]
```

---

### `values()`

Returns all values in a map.

Example:

```
values({
  env = "dev"
  app = "web"
})
```

Result:

```
["dev","web"]
```

---

### `lookup()`

Retrieves a value from a map using a key.

Example:

```
lookup({
  dev = "t3.micro"
  prod = "t3.large"
}, "prod")
```

Result:

```
t3.large
```

Usage example:

```
instance_type = lookup(var.instance_types, var.environment)
```

### zipmap Function

- **Purpose:** Creates a **map from two lists** — one list for keys and another for values.
    
- **Syntax:**
    

`zipmap(keys, values)`

| Argument | Description                                |
| -------- | ------------------------------------------ |
| keys     | A list of strings to be used as map keys   |
| values   | A list of values corresponding to each key |

- **Important:** The two lists must have the **same length**, otherwise Terraform will throw an error.
    

---

### Example 1 — Basic Usage

```
variable "keys" {  
  default = ["name", "env", "region"]  
}  
  
variable "values" {  
  default = ["webserver", "prod", "us-east-1"]  
}  
  
output "my_map" {  
  value = zipmap(var.keys, var.values)  
}
```

**Result:**

```
{  
  "name"   = "webserver"  
  "env"    = "prod"  
  "region" = "us-east-1"  
}
```
---

### Example 2 — Using Lists Dynamically

```
locals {  
  servers = ["app1", "app2", "app3"]  
  ips     = ["10.0.0.1", "10.0.0.2", "10.0.0.3"]  
}  
  
output "server_map" {  
  value = zipmap(local.servers, local.ips)  
}
```
**Result:**

```
{  
  "app1" = "10.0.0.1"  
  "app2" = "10.0.0.2"  
  "app3" = "10.0.0.3"  
}
```
- This is very useful when you need **dynamic mapping**, e.g., **servers to IPs**, **names to ports**, etc.
    

---

### Example 3 — Combining with For Expressions

```
locals {  
  ports = [80, 443]  
  names = ["http", "https"]  
}  
  
output "port_map" {  
  value = zipmap(local.names, local.ports)  
}
```

**Result:**
```
{  
  "http"  = 80  
  "https" = 443  
}
```
- Makes **config generation very flexible** for modules and resource attributes.
    

---

### Must-Know Points

- `zipmap` **always returns a map**.
    
- **Keys and values must match in length**.
    
- Commonly used to **dynamically generate maps** for:
    
    - Resource tags
        
    - Security group rules
        
    - Config maps for modules

```
tostring(8080)
```

```
"8080"
```

---

### `tonumber()`

Converts a value to number.

Example:

```
tonumber("8080")
```

Result:

```
8080
```

---

### `tolist()`

Converts a value to list.

Example:

```
tolist(["a","b"])
```

---

### `tomap()`

Converts a value into a map.

Example:

```
tomap({
  env = "dev"
})
```

---

# File Functions

Used to read local files.

### `file()`

Reads the contents of a file.

Example:

```
file("userdata.sh")
```

Used for EC2 user data:

```
user_data = file("userdata.sh")
```

---

### `filebase64()`

Reads a file and encodes it in Base64.

Example:

```
filebase64("script.sh")
```

Commonly used for:

- cloud-init
- user data scripts

---

# IP Network Functions

Useful for networking configurations.

### `cidrsubnet()`

Creates a subnet from a larger CIDR block.

Example:

```
cidrsubnet("10.0.0.0/16", 8, 1)
```

Result:

```
10.0.1.0/24
```

Used when dynamically generating subnets.

---

### `cidrhost()`

Returns a specific IP from a subnet.

Example:

```
cidrhost("10.0.1.0/24", 5)
```

Result:

```
10.0.1.5
```

# Real DevOps Example

Dynamic subnet creation:

```
resource "aws_subnet" "subnets" {
  count = 3

  cidr_block = cidrsubnet(var.vpc_cidr, 8, count.index)
}
```

If:

```
vpc_cidr = 10.0.0.0/16
```

Terraform generates:

```
10.0.0.0/24
10.0.1.0/24
10.0.2.0/24
```

# Key Things to Remember

- Terraform functions are **built-in and cannot be custom-defined**
- Functions are evaluated during **plan and apply**
- Functions can be **nested**

Example:

```
upper(format("web-%d", count.index))
```

Result:

```
WEB-0
WEB-1
```

- Functions help make Terraform configurations **dynamic, reusable, and maintainable**.
