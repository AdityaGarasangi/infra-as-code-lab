## What is a Backend?

A **backend** in Terraform determines **where the Terraform state file is stored and how operations like locking are handled**.

By default, Terraform uses a **local backend**, which stores state on the local machine.

Using a backend allows teams to **store state remotely and collaborate safely**.

---

# Default Backend (Local)

If no backend is defined, Terraform uses:

```
terraform.tfstate
```

Stored locally in the project directory.

### Problem

- Not suitable for teams
- No locking
- Risk of state conflicts

---

# Backend Configuration

Backend is configured inside a **terraform block**.

```
terraform {  
  backend "s3" {  
    bucket = "terraform-state-bucket"  
    key    = "dev/terraform.tfstate"  
    region = "us-east-1"  
  }  
}
```

This tells Terraform to **store the state remotely in S3**.

---

# Common Backend Types

|Backend|Use Case|
|---|---|
|`local`|Default local storage|
|`s3`|AWS remote state|
|`azurerm`|Azure Storage|
|`gcs`|Google Cloud Storage|
|`remote`|Terraform Cloud|
|`http`|Custom remote server|

---

# Example: S3 Backend with Locking

```
terraform {  
  backend "s3" {  
    bucket         = "terraform-state-bucket"  
    key            = "prod/terraform.tfstate"  
    region         = "us-east-1"  
    dynamodb_table = "terraform-locks"  
  }  
}
```

### What this does

- **S3 bucket** → stores state file
- **DynamoDB table** → manages state locking

---

# Backend Initialization

After configuring a backend, run:

```
terraform init
```

Terraform will:

- Configure the backend
- Move existing state if needed
- Prepare remote state storage

---

# Backend Reconfiguration

If backend settings change:

terraform init -reconfigure

This forces Terraform to **reinitialize the backend**.

---

# Important Points

- Backend must be defined **only once per configuration**.
- Backend configuration is processed during **`terraform init`**.
- State files should **not be committed to Git**.
- Remote backends enable **team collaboration and locking**.

---

Backends are essential for **secure and collaborative Terraform state management**.
