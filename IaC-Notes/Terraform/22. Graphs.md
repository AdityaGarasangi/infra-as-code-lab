- **`terraform graph` generates a visual representation of the Terraform dependency graph.**
- Terraform internally builds a **dependency graph of all resources** to determine **the correct order of creation, modification, and destruction**.
- The `terraform graph` command lets you **see this dependency relationship between resources**.

---

- Basic syntax:

```
terraform graph
```

This outputs a **Graphviz DOT format graph**.

Example output:

```
digraph {
  "aws_vpc.main"
  "aws_subnet.public"
  "aws_instance.web"

  "aws_vpc.main" -> "aws_subnet.public"
  "aws_subnet.public" -> "aws_instance.web"
}
```

This means:

```
aws_vpc.main
      ↓
aws_subnet.public
      ↓
aws_instance.web
```

Terraform will create resources in this order.

---

### Visualizing the Graph

Since Terraform outputs **DOT format**, you usually convert it into an image using **Graphviz**.

Install Graphviz first.

Example command:

```
terraform graph | dot-Tpng > graph.png
```

This generates:

```
graph.png
```

Which visually shows the dependency graph.

---

### Example Terraform Configuration

Example:

```
resource "aws_vpc" "main" {
  cidr_block = "10.0.0.0/16"
}
```

```
resource "aws_subnet" "public" {
  vpc_id = aws_vpc.main.id
}
```

```
resource "aws_instance" "web" {
  subnet_id = aws_subnet.public.id
}
```

Dependency graph:

```
aws_vpc.main
      ↓
aws_subnet.public
      ↓
aws_instance.web
```

Terraform determines this automatically using **attribute references**.

### Why Terraform Graph Is Useful

It helps you:

|Use Case|Purpose|
|---|---|
|Understand infrastructure dependencies|See how resources connect|
|Debug dependency issues|Identify incorrect references|
|Visualize complex infrastructure|Large environments with many resources|
|Understand execution order|See which resources depend on others|

---

### Example with Parallel Execution

If two resources are independent:

```
resource "aws_s3_bucket" "logs" {}
```

```
resource "aws_security_group" "web" {}
```

Graph:

```
aws_s3_bucket.logs

aws_security_group.web
```

No connection means Terraform can **create them in parallel**.

---

### Using `depends_on` in Graph

Example:

```
resource "aws_instance" "web" {
  depends_on = [aws_security_group.web]
}
```

Graph:

```
aws_security_group.web
         ↓
aws_instance.web
```

Manual dependency appears in the graph.

---

### Filtering the Graph

For very large infrastructures, the graph can become **extremely large**.

Terraform supports filtering:

```
terraform graph-type=plan
```

Types available:

|Option|Purpose|
|---|---|
|`plan`|Graph for plan execution|
|`apply`|Graph used during apply|
|`validate`|Graph for configuration validation|

### Important Points to Remember

- `terraform graph` shows the **resource dependency graph**.
- Terraform uses this graph to determine **execution order**.
- The output is in **Graphviz DOT format**.
- You can convert it into diagrams using:

```
terraform graph | dot-Tpng > graph.png
```

- Useful for **debugging infrastructure dependencies**.
- Independent resources in the graph **run in parallel**.

---

- Terraform allows you to **save the execution plan to a file** so it can be **reviewed and applied later**.
- This is commonly used in **CI/CD pipelines** to ensure the exact plan that was reviewed is the one that gets applied.

---

- Basic syntax:

```
terraform plan-out=tfplan
```

This saves the plan to a file named:

```
tfplan
```

---

- To apply the saved plan:

```
terraform apply tfplan
```

Terraform will execute **exactly the actions stored in that plan file**.

---

- Important behavior:

|Point|Explanation|
|---|---|
|Plan file is binary|It cannot be edited manually|
|Ensures consistency|`apply` uses the exact reviewed plan|
|Prevents drift between plan and apply|Useful in automated pipelines|
