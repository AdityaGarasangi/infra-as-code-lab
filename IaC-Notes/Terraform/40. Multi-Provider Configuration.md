## What is Multi-Provider Configuration?

**Multi-provider configuration** allows Terraform to use **multiple providers or multiple configurations of the same provider** in a single project.

This is useful for managing:

- Multiple **cloud providers** (AWS, Azure, GCP)
- Multiple **regions**
- Multiple **accounts**

---

# Basic Example (Multiple Providers)

```
provider "aws" {  
  region = "us-east-1"  
}  
  
provider "google" {  
  project = "my-project"  
  region  = "us-central1"  
}
```
Terraform can now manage **AWS + GCP resources together**.

---

# Multiple Configurations of Same Provider (Aliases)

You can define multiple configurations using **`alias`**.

## Example: Multiple AWS Regions

```
provider "aws" {  
  region = "us-east-1"  
}  
  
provider "aws" {  
  alias  = "west"  
  region = "us-west-2"  
}
```

---

# Using Provider Alias in Resources

```
resource "aws_instance" "east" {  
  provider = aws  
  ami      = "ami-123456"  
}  
  
resource "aws_instance" "west" {  
  provider = aws.west  
  ami      = "ami-654321"  
}
```

---

# Using Providers in Modules

You can pass specific providers to modules.

```
module "app" {  
  source = "./modules/app"  
  
  providers = {  
    aws = aws.west  
  }  
}
```

This ensures the module uses the **correct provider configuration**.

---

# Common Use Cases

## 1. Multi-Region Deployment

- Deploy resources in **different regions**

## 2. Multi-Account Setup

- Use different AWS accounts with separate credentials

## 3. Multi-Cloud Infrastructure

- Combine AWS + Azure + GCP in one setup

---

# Important Points

- Use **`alias`** for multiple configurations of the same provider.
- Default provider is used when no alias is specified.
- Resources must explicitly reference provider when using aliases.
- Modules can receive specific provider configurations.

---

# Best Practices

|Practice|Why|
|---|---|
|Use aliases clearly|Avoid confusion|
|Separate configs per region/account|Better organization|
|Pass providers explicitly to modules|Prevent mistakes|
|Avoid hardcoding credentials|Use env variables|
