- _**terraform init**_ → Initializes the working directory by downloading required providers and configuring the backend.
- _**terraform validate**_ → Checks whether the configuration is syntactically valid and internally consistent
- _**terraform plan**_ → Creates an execution preview showing what Terraform will create, change, or destroy
    - `terraform plan-out=tfplan` → Creates an execution plan and saves it to a file so the exact plan can later be applied using `terraform apply tfplan`.
    - `terraform plan -target=<resource_type>.<resource_name>` → allows you to apply, plan, or destroy specific Terraform resources instead of the entire configuration, mainly used for debugging or partial changes.
- _**terraform apply**_ → Executes the planned changes to reconcile real infrastructure with the desired state
    - `terraform apply -target=<resource_type>.<resource_name>` → allows you to apply, plan, or destroy specific Terraform resources instead of the entire configuration, mainly used for debugging or partial changes.
- _**terraform destroy**_ → Removes all managed infrastructure defined in the configuration
    - `terraform destroy -target=<resource_type>.<resource_name>` → Only destroy this resource (and anything that strictly depends on it). `terraform destroy -target aws_instance.web`
- _**terraform fmt**_ → Formats Terraform code according to standard style conventions.
    - `terraform fmt -diff` → Displays a preview of formatting changes (differences) without actually overwriting your files.
    - `terraform fmt -revursive` → Formats Terraform code in the current directory and all sub-directories simultaneously.
    - `terraform fmt -check` → Checks if code is properly formatted and returns a non-zero exit code if any files need changes (ideal for CI/CD pipelines).
- _**terraform show**_ → Displays detailed information about the current state or a saved plan.
- _**terraform state list**_ → Lists all resources currently tracked in the state file
- _**terraform state show**_ → Displays detailed information about a specific resource in the state.
- _**terraform refresh**_ → Updates the state file to match real-world infrastructure without changing resources (legacy behavior, mostly integrated into plan now).
- _**terraform import**_ → Brings existing infrastructure under Terraform management without recreating it.
- _**terraform output**_ →Displays output variables defined in the configuration.
    - `terraform output <variable>` → displays the value of a specific output variable defined in the Terraform configuration.
- _**terraform workspace**_ → Manages multiple state environments within the same configuration
- _**terraform providers**_ → Shows which providers are required by the configuration.
- _**terraform taint →**_ Used to mark a resource for forced recreation.
    - `terraform taint <resource_type>.<resource_name>`
